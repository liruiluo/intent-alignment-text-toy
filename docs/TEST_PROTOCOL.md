# 冻结测试协议：intent-alignment-text-toy-v1.1

## 1. 测试问题

Qwen3.5-4B 能否在一个最小文字交互环境中，将中文位移意图转换成逐步动作，并在限定动作数内到达目标？

代表性任务：`在5步以内向右走3米。`

## 2. 环境语义

- 智能体从 `(0, 0)` 出发。
- `UP / DOWN / LEFT / RIGHT` 每次沿对应方向移动1米；坐标变化分别为 `(0,+1) / (0,-1) / (-1,0) / (+1,0)`。
- 每道题最多允许1–5个移动动作。
- 到达目标坐标时环境自动结束。
- 非法输出立即结束并判失败；超过预算仍未到达目标也判失败。
- 主判据是“是否在预算内到达目标状态”，不要求唯一最短动作序列。

这与原测试大纲中“若干步以内移动若干米”的目标状态语义一致。例如，`在5步以内向右走3米` 的最直接解是连续3次 `RIGHT`。

## 3. 数据

`data/intent_alignment_20.jsonl` 固定20道题：

- 四个方向各5题；
- 最短动作长度1、2、3、4、5各4题；
- 每题动作预算不超过5；
- 使用不同但无歧义的中文表达。

## 4. 模型与解码

- 模型：本地 Qwen3.5-4B text-only checkpoint（冻结路径和配置哈希写入结果）。
- 模式：zero-shot，不训练、不微调。
- 解码：greedy，`do_sample=false`，thinking关闭。
- 每轮只允许输出一个动作标签，环境返回新坐标与剩余预算后继续。

## 5. 指标

样本成功率：

```text
success_rate = 成功题数 / 20
```

- “95%以上”：至少19/20。
- 若文字严格要求“高于95%”：20题规模下只能20/20。

20题只构成快速功能性 pilot。即使得到20/20，也不能据此在统计意义上证明模型面对所有同类表达的真实成功率高于95%；正式泛化主张需要扩大独立测试集。

## 6. 结论边界

本测试能够证明：模型在该冻结 toy 任务集上具备基本的中文意图到动作闭环能力。

本测试不能证明：

- 已接入真实 Minecraft / MineRL；
- 已覆盖智能体与专家、智能体与智能体等全部交互模式；
- “认知偏差降低至初始值5%以下”这一相对收敛指标；
- 面向未见表达的总体成功率必然超过95%。

## 7. 协议修订记录

- v1 首次运行保留在 `results/qwen3.5-4b-zero-shot-v1-under-specified-coordinates.json`，结果为18/20。
- v1 的 prompt 显示坐标，却未声明方向与坐标正负号的映射；两条失败均为负坐标方向反转。
- v1.1 只补齐通用动作语义映射；数据、模型、解码、动作预算与评分均不变。两次结果必须同时保留，避免隐去提示词修订。
