可解释协议 · 最小 Agent

这是 Agent Loop，不是一次性生成动作串

每一轮模型只选择一个动作，环境执行后再把新状态反馈给模型。这样可以直接观察意图理解、状态跟踪和预算约束是否共同成立。

一次完整交互循环

01

环境观察

提供用户意图、当前位置、剩余动作数和此前动作。

02

Qwen3.5-4B 决策

根据当前状态预测下一步，不一次性输出整条路线。

03

固定原子动作

只接受 UP、DOWN、LEFT、RIGHT；每次恰好移动 1 米。

04

环境更新与终止

到达目标即成功；非法动作或预算耗尽则结束。

本次没有开启显式 Reasoning

enable_thinking = false

模型不输出 <think>...</think> 或解释文字，每轮直接给出一个动作标签。这是一条干净的 direct-action policy 基线；模型前向计算仍存在内部表征，但没有额外的显式推理 token。

while not env.terminated:
  observation = goal + position + remaining_budget + history
  action = qwen(observation)  # one label only
  env.step(action)         # returns the next state

本次结论能说明什么

可以说明

在冻结 test100 上，训练前后都完成 100/100；veRL 确实执行了一个 GRPO optimizer update，tensor 证据确认参数发生变化。

不能外推

训练前已经满分，所以本轮没有证明成功率提升；文字 toy 结果也不能代表 Minecraft / MineRL 真环境表现或所有中文表达的总体成功率。

参数更新如何确认

veRL 将两分片 BF16 base checkpoint 导出为单文件 FP32 model.safetensors。审计按 tensor key 和数值比较：文本 policy core 的 426 个 key 一致，6/6 个固定 probe 发生 FP32 变化，且有 8 个值在 BF16 精度下仍变化。文件名或整文件 hash 变化不单独作为学习证据。
